## 实际验证

- 只在 `/tmp/protoloft-preference-review-20261105` 复制运行文件，初始化合成管理员与空库；浏览器使用 `http://127.0.0.1:8788/`。没有访问或编辑现有站点业务数据。
- 空状态：点击“发布首个原型”，观察“暂无可用项目”；点击“新建项目”，确认文件夹下拉无选项。未提交新建请求。
- 个人设置：观察三个蓝色主按钮均 enabled；读取 opt-tag 的 computed color/fontSize 与弹窗背景，并按 sRGB 线性亮度公式计算对比度。
- 键盘：弹窗打开后读取 BODY 焦点；按 Tab，背景控制中心按钮获得焦点，insideModal=false。
- 系统设置：读取真实 DOM 的 labels、aria-label、aria-labelledby 和 tabindex。修改合成组织名再失焦，观察仅以 Toast 提示保存完成。没有发送群消息。
- 保存探针：`node .dev/tmp/preference-autosave-probe.js`，直接装载当前 apiFetch/executeAutoSaveSettings，用受控 pending fetch 依次提交不同快照。输出：actualRequests=1、sentTitle=第一次修改、currentInput=第二次修改、successNotices=[设置已保存, 设置已保存]。这是新增准确性证据，不能由上一轮通过的其他回归代替。
- 短窗口：1280×600 时个人设置内部 overflow=auto，向下滚动后通知保存按钮位于 y=520.77–558.77，可访问；因此没有报告“永久裁切”。恢复默认视口。
- 控制台 error/warn 列表为空。本轮没有重复执行与只读审查无关的业务回归；未进行真实网络慢速/断网 HTTP 复现、屏幕阅读器验收或全站无障碍合规判断。

## 结论

Block：自动保存准确性、首次动作和已验证的键盘/可读性问题仍需处理。建议先修可靠性与可操作性，再做个人设置与说明文案的减法，不另起视觉风格。
