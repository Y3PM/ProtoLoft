## [P2] 头像保存的旧响应覆盖后续草稿

审核时位置：`assets/js/app.js:2965-2966`（`saveProfileAvatar` 成功回调，后续修复已改变行号）。

**触发条件**：保存请求尚未完成，用户继续选择另一个造型或配色。当前只禁用保存按钮，造型和颜色仍然可以编辑。

**实际复现**：

1. 临时站中已保存 `head-mint`（松石青 · 象首）。
2. 选择 `walk-mint`（松石青 · 迈步），点击保存。
3. 等待期间改选 `bow-coral`（陶珊瑚 · 低头）。真实选板保持开启，头像预览为新草稿，保存按钮禁用。
4. 旧请求成功返回后，头像被改回 `walk-mint`，选板自动关闭，后续 `bow-coral` 草稿被丢弃。

测试仅在临时副本的 `profile_update_avatar` 分支加入 7 秒延迟模拟慢网络/慢服务，未替换任何前端或业务判断。临时站和测试数据已清理。

记录值：

```json
{
  "duringSave": {"open": true, "pose": "bow", "saving": true, "theme": "coral"},
  "afterSave": {"open": false, "pose": "walk", "theme": "mint"}
}
```

**原因**：成功回调无条件 `renderMyProfileAvatar(confirmed)` 和 `closeProfileAvatarPicker(false)`，没有判断当前草稿是否仍等于请求快照 `targetId`，也没有判断该选板是否已在期间关闭、重新打开。

**建议**：保存期间统一锁定造型/颜色，或为编辑草稿与选板生命周期记录序号。若草稿或选板上下文已变化，只更新已保存值，保留当前新草稿并恢复保存按钮；不要由旧响应关闭新一轮编辑。

证据：[状态 JSON](2026-11-25-recent-changes/avatar-draft-lost.json)、[保存期间的新草稿](2026-11-25-recent-changes/avatar-draft-during-save.jpg)、[旧响应返回后](2026-11-25-recent-changes/avatar-draft-after-save.jpg)。
