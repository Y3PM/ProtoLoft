# 项目负责人模型与发布入口复核 · 2026-11-20

本次在 Gemini 已有未提交修改上局部修复，保留其他修改。结果已在本地隔离安装与 Chrome 验证，随后按用户授权完成 FTP 部署；不改动实际站点数据库与上传资源。

## 最终行为

- 账号角色仍为管理员、协作者、审阅人，成员权限表没有增加开关。
- 原型项目只有“项目负责人”多选框；空选择为“全部协作者”，有选择时按指定名单限制发版、日常版本协作与分享管理，管理员保留权限。
- 创建者不在指定名单时也不能发版，但仍能修改项目配置、调整负责人范围和删除整个项目；其他指定负责人不能调整范围或删除整个项目。
- 默认开放项目中，其他协作者可发版、管理版本和分享；项目名称、文件夹等基础配置仍由创建者和管理员维护。
- 同名版本覆盖和版本删除继续按发布者归属保护；RP 底稿的补传、更换、移除也受同样保护，且还需具备当前项目协作权限。现有版本名称/日志编辑和默认版本切换规则保持原样。
- 没有可发布项目但存在他人指定项目时，“发布版本”提示新建项目或联系创建者；有可用项目时直接打开发布窗。空站点保留先建项目再发布的流程。
- 外链不显示项目负责人选择，列表保留创建者名称，分享配置不因默认开放项目规则而扩大权限。

## 发现及修复

1. **创建者绕过指定名单**：原后端 `canEditItem` 仍无条件放行创建者，而新建控制中心行的前端判断未传创建者，造成首次保存和刷新后的发版入口不一致。现在项目发版统一按名单判断，创建者的管理权限独立保留。
2. **指定负责人未计入交接与删除保护**：成员统计、删除守卫和交接只查询 `created_by`，管理员创建后指定给其他人的项目会被遗漏。现在同时覆盖创建者归属和指定负责人资格，按项目去重；交接替换并去重指定名单，开放模式保持为空，版本发布者和姓名快照保持原样。保存、删除检查和交接在 SQLite 写事务中处理；交接在锁内重新确认接管人状态。
3. **他人 RP 底稿可被替换或移除**：原接口只检查项目协作权。现在接口和版本卡片都限制为版本发布者或管理员；写入事务中重查权限和内容代际，拒绝将底稿写入已经被替换的旧版本目录。
4. **负责人变化后入口滞后**：保存负责人范围时，现在同步控制中心行、侧栏和发布下拉，立即增减上传入口；交接也同步指定名单与编辑按钮数据，避免重开弹窗恢复旧负责人。
5. **成员候选重绘会清空停用负责人**：原刷新只保留活跃候选，唯一指定成员停用后可能被默默改成全员开放。现在保留原有已选项并标注停用状态，新增负责人仍要求正常账号；无效名单格式、审阅人和不存在的成员会被拒绝，不退化为全员开放。
6. **外链混入项目模型**：撤出外链负责人选择和“全部协作者”展示，恢复外链原有配置权限。新负责人控件样式收进 `app.css`，复用已有表单和徽标类。

技术字段仍使用 `collaborators` 保存指定名单；未迁移 Schema、技术标识或存储路径，未增加构建与运行依赖。
