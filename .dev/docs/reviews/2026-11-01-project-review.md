**需要调整的规则与沟通习惯**

1. **把绝对描述改成可核对的证据。** 历史记录多次出现“100% 通过”“彻底根除”“0 毫秒”，但当前仓库找不到记录中列出的那些测试脚本；只能确认文档这样记载，不能复验其范围和断言。以后记录具体命令、目标版本、角色、断言、结果与未覆盖项。不要用“返回 200”“源码有某段字符串”替代业务验收。
2. **安全规则表达不变量，避免把手段当结果。** “350ms 物理防重”不是互斥；“只允许 HTTP”不是完整的 SSRF 防护；“同源 JS 守卫”不是资源鉴权。应改写为“同一业务请求未结束前不能重复执行”“未授权请求拿不到资产内容”“被拒绝的操作不改变文件与数据”。
3. **权限使用三维描述：角色 × 操作 × 对象。** “协作者可以管理”不能推导为可以删除所有文件夹中的所有项目。测试必须至少包含：本人项目、共管项目、无关项目，以及 Owner、普通管理员、协作者、审阅人和匿名身份。
4. **把失败后的状态纳入验收。** 对被拒绝的覆盖、损坏 ZIP、丢分片、断网重试、跨项目快速切换，断言旧文件、默认版本、署名和当前上下文保持正确。单看错误提示无法发现本次审查中的多项问题。
5. **“纯净 Schema”应与显式升级流程并存。** 可以删除每次请求里的历史探测补丁，但应保留单独、可备份、可重跑、有版本号的升级入口。新装 DDL 无法替代存量数据库迁移。
6. **把稳定测试从临时部署脚本中分离。** 后续应保留可在隔离目录运行的长期回归测试；测试、打包、发布分别执行。回归测试不得依赖生产数据清理来证明成功。
7. **文案简洁允许必要例外。** 现规则既要求考虑恢复，又在历史记录中把“不可恢复”等说明统称为冗余；应保留操作对象、影响范围、恢复条件等确实影响决策的信息。空状态趣味文案作为可选风格，不强制用于权限错误、审批和数据丢失场景。
8. **避免继续增加同义规则。** 建议 AGENTS.md 保留产品约束、协作边界和验证要求；组件规格交给 CSS/组件，历史过程留在 CHANGELOG，实际证据放独立审查或测试记录。新规则优先替换过时规则。

以上是本项目的建议，没有写入全局记忆，也没有自动修改项目规则。Linear 配色、PHP/SQLite 技术栈、具体尺寸与趣味文案不应推广为其他项目的默认要求。

**代码审查发现（按风险排序）**

P0 表示可直接突破关键安全边界，需立即优先修复；P1 表示高风险安全、数据损坏或核心流程失败；P2 表示明确的功能、维护或一致性问题。标为“源码”的问题未执行 PHP/HTTP 复现；SQL 和 JS 实验的边界见文末。

**R01 · P0 · 固定 Cookie 分支绕过身份认证**

位置：[includes/auth.php:312](../../../includes/auth.php:312)。

当没有有效 Session 时，`ue_admin_auth` 的固定值分支直接将用户设为 1，跳过随机 Token 池与密码校验。新安装的首位用户通常正是启用的 Owner，因此匿名请求能取得其身份。后面的数据库查询仅检查账号存在和启用，无法弥补认证绕过。

建议删除固定凭证兼容入口；历史凭证一律失效并重新登录。不要把此类分支保留为调试或自动化捷径。证据：完整认证调用链源码。

**R02 · P1 · 匿名请求可以读取项目批注和回复**

位置：[includes/actions/annotations.php:8](../../../includes/actions/annotations.php:8)。

`list_annotations` 只检查功能开关和项目 ID，不检查登录、项目可见性、分享短码或访问口令。API 网关也没有补上这层检查。默认开关开启时，匿名请求可按项目 ID 读取内部批注、姓名、部门和回复，即使工作台要求登录、项目已隐藏或分享受密码保护。

建议统一项目读取授权；若支持外发页批注，须绑定已验证的分享上下文及其版本，而非放开公共列表。证据：源码。

**R03 · P1 · 删除文件夹绕过其中项目的删除权限**

位置：[includes/actions/items.php:26](../../../includes/actions/items.php:26)。

协作者通过 `canManage()` 即可删除任意文件夹，循环删除其中所有人的项目和物理资源；没有逐项调用 `canDeleteItem()`。同一用户直接删除他人项目会被拦截，但改为删除文件夹便能绕过。

建议先完整预检所有子项目的删除权限，再执行整体删除；或明确将文件夹删除限定为管理员。证据：源码，删除 SQL 子集在内存数据库执行。

**R04 · P1 · 旧上传接口缺少项目级发版权限**

位置：[includes/actions/versions.php:241](../../../includes/actions/versions.php:241)。

`version_upload` 仍可通过网关调用，但查到项目后没有执行 `canEditItem()`。任意协作者可向他人项目发布新版本，且新版本会清除其他默认版本并成为默认。新接口 `version_publish` 已检查项目权限，两条路径存在安全差异。

建议停用旧入口，或让两条入口进入同一发布实现并统一鉴权。证据：源码。

**R05 · P1 · 覆盖权限在删除和写入文件之后才检查**

位置：[includes/actions/versions.php:106](../../../includes/actions/versions.php:106)、[includes/actions/versions.php:178](../../../includes/actions/versions.php:178)。

项目共管人覆盖另一位成员发布的同名版本时，先清除旧资源、解压新 ZIP、可能写入 RP 并更新默认标记，最后才按版本发布人拒绝覆盖。接口虽返回失败，实际原型内容已经变化。旧上传入口也有同样顺序。

建议任何目录创建、清理、分片消费和默认版本修改之前完成全部授权。证据：源码操作顺序。

**R06 · P1 · 使用可改名称作为存储标识，会跨项目覆盖或删除资产**

位置：[includes/actions/versions.php:63](../../../includes/actions/versions.php:63)、[includes/actions/items.php:164](../../../includes/actions/items.php:164)。

路径仅由空间、清洗后的项目名和版本名拼接，未包含项目 ID。不同文件夹允许同名项目，它们发布同版本名会写入同一路径；删除其中一个项目会删除双方共用目录。不同原始名称清洗后相同也会冲突。项目重命名只改数据库，之后删除又按新名称推导目录，旧资源因此残留。

建议存储路径使用不可变的项目/版本标识，显示名独立；删除使用明确记录的存储根目录。已有资产须单独迁移，不能直接更改公式。证据：源码，未改动真实文件。

**R07 · P1 · 合法覆盖失败也可能毁掉原版本**

位置：[includes/actions/versions.php:106](../../../includes/actions/versions.php:106)。

即使用户有权覆盖，代码仍先删旧文件再验证并解压新包。损坏 ZIP、非法条目、缺入口、RP 合并失败或落盘失败都会使旧记录继续指向已删除/部分替换的资源。默认版本切换和版本保存也没有整体事务。

建议新包写入独立暂存目录，全部验证完成后切换；失败只清理暂存资源，保留旧版。文件切换与数据库提交应有明确失败恢复策略。证据：源码。

**R08 · P1 · 驳回申请接口可直接停用正式成员和 Owner**

位置：[includes/actions/users.php:100](../../../includes/actions/users.php:100)。

`reject_user` 的 UPDATE 没有 `status = 0` 条件，也未调用管理员保护规则。普通管理员可以指定正式 Owner、其他管理员或自己，将其状态改成驳回，绕过 `updateUser()` 和 `deleteUser()` 的保护。

建议审批与驳回仅处理待审批申请，检查实际影响行数；不能把前端只显示申请行当作授权。证据：源码 + 内存 SQLite 用实际 UPDATE 成功修改合成 Owner。

**R09 · P1 · 停用或删除账号后触发认证递归**

位置：[includes/auth.php:359](../../../includes/auth.php:359)、[includes/auth.php:170](../../../includes/auth.php:170)。

`getCurrentUser()` 发现 Session 所指用户无效时调用 `logout()`；`logout()` 第一件事又调用 `getCurrentUser()`。Session 尚未清理、缓存仍为 null，会不断相互调用。已登录成员被停用或删除后，下次访问可能耗尽请求内存，无法正常退出。

建议无效身份分支直接清理凭证；注销记录只使用已验证身份，不重新进入身份解析。证据：源码调用链，未执行 PHP 内存耗尽实验。

**R10 · P1 · 新装数据库不能执行个人修改密码**

位置：[includes/auth.php:1404](../../../includes/auth.php:1404)、[includes/db.php:65](../../../includes/db.php:65)。

修改密码与忽略首次提示都写入 `is_first_login`，新装 users 表却没有该列；安装也不补充。实际 SQL 在全新 Schema 中报 `no such column: is_first_login`。此外当前用户查询不读取该字段，首次提示本身也不能按原逻辑显示。

建议明确保留还是移除首次提示功能，使 Schema、查询、更新和前端契约一致。证据：内存 SQLite 从当前 DDL 建表后执行实际改密 SQL。

**R11 · P1 · 大盘 JSON 输出误用参数，破坏管理页面渲染**

位置：[includes/modals.php:885](../../../includes/modals.php:885)。

多处使用 `json_encode(..., ENT_QUOTES, 'UTF-8')`；第三个参数应是最大深度整数，并非字符集。PHP 7 中会发生参数警告、输出失败并形成不完整 JS；PHP 8 中会抛出类型错误。该代码位于主页面包含的管理弹窗中，影响不限于点开图表时。

建议使用 JSON 专用 flags 和正确的整数 depth；HTML 转义与脚本中的 JSON 编码分别处理。证据：源码；本机缺 PHP，未执行各版本运行验证。

**R12 · P1 · 自主申请姓名可注入管理员按钮的 JS**

位置：[assets/js/admin.js:113](../../../assets/js/admin.js:113)、[assets/js/admin.js:1283](../../../assets/js/admin.js:1283)。

`esc()` 使用文本节点的 innerHTML 序列化，不能提供 JS 字符串或 HTML 属性上下文的安全编码。申请姓名被放入 `onclick="handleApproveUser(id, '姓名')"`；单引号可以跳出字符串。注册开放时，尚未获批的申请人也能写入此数据，管理员点击批准/驳回时触发。同类写法还用于交接按钮。全局 admin.js 的同名 esc 也会覆盖 app.js 的版本。

建议移除动态内联事件，使用数据属性和事件监听，只把数值 ID 传给动作；姓名通过 textContent 展示。证据：实际 esc 和按钮模板在 Node VM 中执行合成姓名，成功触发无副作用探针赋值；DOM 为最小模拟，未进行浏览器攻击验证。

**R13 · P1 · 静态资产没有对应的服务端访问控制**

位置：[uploads/.htaccess:8](../../../uploads/.htaccess:8)、[includes/zip_handler.php:108](../../../includes/zip_handler.php:108)、[README.md:141](../../../README.md:141)。

仓库提供的 Apache 规则只禁止脚本、目录列表和跨域嵌入，没有阻止直接读取 `.rp` 或原型文件。RP 本身落在 Web 静态目录；即使下载 API 鉴权正确，知道路径的人仍可直接请求。HTML 的跳转 JS 不会阻止 HTTP 客户端取得正文、JS、图片等，也无法落实分享口令、撤销或过期。

建议至少从 Web 层禁止所有 RP 静态下载；需要保证原型私密性时，通过服务端资源网关或经验证的服务器内部重定向提供资源。还需明确同源原型脚本的信任边界：当前 iframe 同时开放脚本与同源能力，不能隔离恶意上传者与宿主。证据：仓库配置和源码；没有检查实际生产服务器额外配置，因此不宣称线上必然可直读。

**R14 · P1 · 管理员和协作者的 CSRF 验证被直接放行**

位置：[includes/config.php:110](../../../includes/config.php:110)、[api.php:129](../../../api.php:129)。

`verify_csrf_token()` 对 `canManage()` 返回 true，不要求有效 Token，甚至把任意传入字符串写成 Session Token。Origin 仅比较主机名，且缺失时完全跳过，不能作为完整替代；不同协议/端口也被视作同来源。批注写接口另有全量 CSRF 豁免。

建议修复 Token 的传递和 Session 根因，恢复严格比对；来源校验比较完整 origin，按接口需求明确例外。测试需覆盖 Cookie 有效但 Token 缺失/错误、同主机不同端口及无 Origin。证据：源码，不声称所有浏览器场景都能跨站利用。

**R15 · P1 · Webhook 允许非受信地址，且关闭 TLS 验证**

位置：[includes/webhook.php:68](../../../includes/webhook.php:68)、[includes/webhook.php:91](../../../includes/webhook.php:91)、[includes/actions/system.php:40](../../../includes/actions/system.php:40)。

测试接口对所有已登录用户开放，服务端仅限制 HTTP/HTTPS，未限制目标主机或地址，能向回环、内网及其他服务发 POST。cURL 和 stream 两条路径都关闭证书验证，通知正文也可能发往被冒充的 HTTPS 端点。cURL 还把传输成功当作送达成功，没有检查 HTTP 和平台业务错误。

建议对声明支持的机器人使用明确域名/路径白名单，若需要通用目标则单独设计管理员授权与地址校验；恢复证书校验，并按响应判断投递结果。证据：源码；本次没有发送任何消息或网络探测。

**R16 · P1 · 隐藏项目的分享配置检查使用不存在的字段**

位置：[includes/actions/shares.php:16](../../../includes/actions/shares.php:16)、[includes/auth.php:847](../../../includes/auth.php:847)。

读取接口检查 `is_hidden`，真实 Schema 和页面使用 `is_visible`。当审阅人获准分享时，可绕过隐藏检查，按 ID 获取隐藏项目的分享配置，其中包含主链密码、专属密码与短码。这些字段不能仅因拥有全局分享能力就无条件全部返回。

**R17 · P1 · 批注旧请求会覆盖新上下文，后端又不验证项目与版本关系**

位置：[assets/js/annotation.js:134](../../../assets/js/annotation.js:134)、[includes/actions/annotations.php:87](../../../includes/actions/annotations.php:87)。

快速从项目 A 切到 B，A 的列表请求若较晚返回，会直接写入 B 的全局状态，包含 A 的 ver_id。下一次提交可形成 B 的 item_id + A 的 ver_id。后端对传入正数版本没有验证归属，直接插入批注，因此数据可被错误关联。

建议请求携带上下文快照/序号，回包仅在上下文仍一致时应用；服务端写前验证项目、版本存在且从属一致，同时检查对象访问权。证据：实际 annotation.js 在重排回包的模拟环境中产生 `item_id=2&ver_id=11`，原本选中的版本应为 22。

**R18 · P2 · 审阅人的个人资料/密码操作缺少 CSRF，机器人测试函数也不可用**

位置：[assets/js/app.js:1039](../../../assets/js/app.js:1039)、[assets/js/app.js:1093](../../../assets/js/app.js:1093)、[includes/modals.php:1806](../../../includes/modals.php:1806)。

**R23 · P2 · 350ms 限制不是请求互斥，也没有自动锁住现有按钮**

位置：[assets/js/admin.js:63](../../../assets/js/admin.js:63)。

请求超过 350ms 仍在执行时，第二次同动作会再次发出；第一个请求 finally 会删除第二个请求共用的锁。锁只按 action 而非对象分组，又会拦截不同对象的快速正常操作。现有调用基本不传第三个按钮参数，所以新增 Loading 逻辑没有自动覆盖已有按钮。服务端也没有据此获得幂等性。

建议以业务对象标识维护 pending promise，按动作需求复用或拒绝并发；按钮状态只是反馈。发版、创建等关键写操作还需数据库唯一约束/幂等设计。证据：实际 adminFetch 源码在受控时钟中发出 3 次请求，其中后两次均在前次未全部完成时启动。
