## 发现

### P2 · 批注抽屉重新打开后无法同步其他成员的更新

位置：`assets/js/annotation.js:392–394`，以及同文件的 `loadedKey` 写入逻辑。

`loadedKey` 只记录项目与版本，没有有效期或服务端更新标记。首次预加载完成后，该键在同一项目与版本内持续命中；重新打开抽屉和原型翻页都跳过请求，现有上下文定时器也不再刷新列表。去除初次重复请求的同时，原先每次开窗重新读取批注的行为丢失了。

复现：打开抽屉看到已有批注，关闭抽屉；另一位已登录协作者通过真实接口新增同页批注；重新打开抽屉。主管理员、审阅人和已授权分享访客均未发出新的 `list_annotations` 请求，新卡片数量为 0。显式调用 `loadAnnotations()` 后，新卡片立即出现，说明服务端数据与权限正常。

建议：仅合并正在进行的重复请求；用户重新打开抽屉时保留重新验证或有界过期刷新，不要将一次成功加载视为本页生命周期内永久有效。

### P2 · 注入的原型增强脚本调用不存在的函数

位置：`includes/zip_handler.php:592–596`。

上传注入的自执行脚本调用 `isAxureEnvironment()`，但此函数只定义在宿主 `app.js` 和 `share.php` 的另一层局部作用域内，注入脚本中没有定义。浏览器也不会跨 iframe 自动解析父窗口的局部函数。

复现：通过真实发布流程上传普通 `index.html`。主管理员、审阅人及分享访客打开后，各产生 44 次 `ReferenceError: isAxureEnvironment is not defined`，来源为每 60ms 执行的增强轮询。页面仍可显示，但原本用于让非 Axure 页面提前结束轮询的分支失效，产生连续未捕获异常。

建议：让注入版本包含自己的 Axure 环境检查，并在普通 HTML 上干净退出。回归需要执行发布后的真实 HTML，并收集 iframe 的 `pageerror`，不能仅检查 PHP/JS 语法或用已具备完整目录树的模拟 DOM 验证。

### P2 · 搜索索引未在被搜索字段变化后失效

位置：`assets/js/app.js:1064–1065`。

缓存只比较 `.item-row` 数量。负责人姓名、项目与目录信息、版本信息的原地同步不会改变数量，缓存中的搜索文本与标题快照继续使用旧值。

复现：先搜索一次项目以建立索引；通过个人设置把姓名从「测试超管」改为「新负责人甲」；关闭个人设置，搜索「新负责人甲」。侧栏显示空结果，但实际项目节点的 `data-creator-name` 已更新为新姓名。清除索引并执行相同搜索后项目立即出现。

建议：在搜索字段成功同步时使索引失效，或引入明确的数据修订号。不能以节点数量作为索引内容未变化的判断依据。

### P2 · 下拉键盘高亮和实际焦点不同步，空格选错选项

位置：`assets/js/ver-picker.js:463–475`，以及 `highlightIndex()`。

方向键只更新 `activeIndex` 和 `.is-active`，焦点仍留在最初选中的按钮。菜单处理了 Enter，没有处理空格，空格触发的是旧焦点按钮的默认 click。

复现：当前版本为 v2，打开顶部版本下拉，按 ArrowDown，界面高亮 v1；按 Space 后菜单收起，实际值仍为 `/asset.php/v2/index.html`。本组件用于全站单选下拉，其他下拉同样存在焦点与高亮脱节的问题。

建议：方向键移动时同步选项焦点，或采用完整的活动后代方案，并将 Enter 与空格统一提交当前高亮项。验证应检查提交后的原生 select 值和实际业务切换结果。
