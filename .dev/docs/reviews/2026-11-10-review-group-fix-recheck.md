## 仍需收敛：空日志被当作静默通知指令

位置：`includes/actions/versions.php:67–81`。

当前缺省分支设置：`$notifyItem = ($changelog !== '')`、`$notifyGlobal = ($changelog !== '')`，日志校验又只针对显式通知参数。因此没有传通知参数、也没有传更新日志时，会发布成功并发送 0 次。

真实 MCP HTTP 复现：项目群与评审群均已配置，`publish_version` 只传项目、版本名及 ZIP 上传 ID，没有传通知参数，也没有传可选的 `changelog`。实际版本成功保存、`notify_results:[]`、机器人调用 0 次。

这与已确认的“默认发送、允许取消”仍不一致：漏填日志不是用户明确取消通知。网页会要求补填日志，MCP 却静默成功，同一发版动作仍有两种规则。

最小修改方向：默认通知不根据日志是否为空改变；当确实要向已配置目标发送但日志为空时，沿用“开启群通知需填写更新日志”的校验。显式关闭通知时继续允许静默；未配置目标时无需无意义地要求日志。

配套测试 `.dev/tests/webhook_split_notify_regression.py:299–309` 仍断言“空日志且省略参数时静默成功”。应改成验证上述统一规则；临时测试夹具若有意静默发布，应显式关闭通知。不要把改变产品规则的预期当作修复通过依据。
