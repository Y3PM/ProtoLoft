# 偏好问题修复 · 2026-11-05

用户在偏好复查后授权实施。沿用现有视觉、原生 PHP/JS/CSS 与组件，不修改品牌资产或数据库 Schema，不增加生产依赖。保留本轮前已有的控制中心、文案和 favicon 修改。

## 用户可见变化

- 系统设置、角色权限保留自动保存，变为每个动作一个请求在途、一个最新快照等待；请求结束后继续发送最后的修改。保存状态在控制中心固定头部显示“保存中…”/“已保存”或失败原因，失败可重试。不会把旧快照成功当作当前草稿成功；无效邮箱域名会阻断排队快照，旧请求完成也不会覆盖错误提示。初始渲染审批接收人不再触发无意义保存。
- 全新工作台仅突出“新建文件夹”；有文件夹无项目时突出“新建项目”；选中未发版项目后仅突出“发布原型”。快速入口缺少前置实体时也会引向创建，而不是只报无可用项目。
- 个人设置默认只展开姓名；改密码、通知使用原生 details/summary 按需展开。资料与通知未修改时保存按钮禁用，提交成功以已经保存的值重新建立基准；保存期间再输入的新草稿仍保持可保存。姓名表单不顺带写入独立管理的通知值。
- 去掉时区、分享上限下的重复解释，组织名称只保留留空含义；安装与设置字段名称一致。辅助文字语义色由 `#8a94a6` 改为 `#667085`，品牌蓝保持不变，搜索/表单占位文字使用可读辅助色。
- 系统设置现有标题关联输入、开关和选择框；角色权限复选框具备名称。控制中心导航和审批接收人触发器改用原生按钮，展开状态明确，Escape 先关闭多选浮层并返回触发器。
- 通用弹窗统一打开/关闭：移入焦点、背景 inert、Tab/Shift+Tab 环绕，关闭返回入口；嵌套弹窗只关闭最上层。确认框的 Enter 使用原生按钮语义，取消按钮不再被全局 Enter 误当作确认。该能力位于全角色 app.js，不依赖 admin.js。

## 浏览器证据

使用 CUA 内置浏览器，隔离副本 `http://127.0.0.1:8789/`，只含合成账号/数据，没有操作用户现有站点。默认桌面尺寸随应用视口变化；个人设置初始截图为 1280×720，另验证 320×600 并恢复默认视口。

1. 从空库点击中心新建文件夹 → 保存 → 中心变为新建项目 → 保存 → 选中项目显示发布原型，三个阶段均可继续。
2. 个人设置默认密码/通知折叠，姓名没有修改时保存禁用；修改后启用。Tab 多次仍在弹窗；Escape 返回个人入口，背景 inert 全部恢复。通知展开后测得辅助文字 `rgb(102,112,133)`，白底对比度 **4.97:1**（此前 3.06:1）。
3. 控制中心 → 新建项目形成嵌套弹窗。Escape 后子窗 display=none、控制中心仍 flex，焦点回到“新建项目”按钮。
4. 系统设置控件在可访问性树有对应名称；审批接收人按钮可以打开选项，Escape 只关闭选项并返回按钮，控制中心保持打开。
5. **真实延迟连续保存**：仅在测试路由给 `save_settings` 加 1.8 秒延迟；第一次改组织名称后，在“保存中…”状态再次改为“最终组织”。完成后状态“已保存”，隔离 SQLite 中 site_title 为“最终组织”，刷新页面仍一致。路由延迟不在生产源码中。
6. 通用确认框 Escape 取消不执行，重新打开后按明确的“退出”按钮正常退出。
7. 审阅人登录后页面不加载 admin.js，仍能打开个人设置、正确移入焦点，并用 Escape 关闭返回入口。控制台 error/warn 为空。
8. 320×600 的精简个人设置边界为 x=9.59–310.39、y=117.23–482.77，位于视口内，焦点在弹窗内。未把这一项当作完整移动端工作台验收。
